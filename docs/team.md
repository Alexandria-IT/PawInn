# Team responsibilities

| Member | Main area | What to explain at the presentation |
| --- | --- | --- |
| 1 | Frontend and integration | Browser-to-API flow, visible error states and the booking demo |
| 2 | Account | Password verification, tokens, authorization and pet ownership |
| 3 | Room and delivery | Availability inputs, inventory guard, Compose, CI and Jenkins |
| 4 | Booking | Room assignment, overlapping requests, checkout, cancellation and audit history |

Each owner reviews their service, contributes verification evidence, and records any remaining defects. Use feature branches and reviewed pull requests. Check the release inside the course container, then build the presentation around one booking journey and its failure case. Do not report measured user outcomes without observations.
